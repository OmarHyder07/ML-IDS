\section{Imbalance}
Because it's so imbalanced we maybe use SMOTE. And that's the thing, we are adjusting the balance of recall and precision. We want to catch as many attacks as possible (recall) at the cost of higher false alarms (precision). Missed attacks cost far more! Optimise recall on the rare attack classes, measured by macro-recall / macro-F1
\paragraph{How solve?} We will conduct a fair test, using the three methods below. Each test will use the same splits for each set. The model will be XGBoost with constant hyper-parameters. 
\paragraph{Measuring success} The metric that we care about most is macro-recall, but macro-F1 is nice to compare as well because we can't just ignore precision. Perhaps we could have an appendix at the end with full eval repots. We should definitely be showing the precision tradeoff too. perhaps one method will have a good balance but another method will have better recall with the tradeoff of bad precision. but still that method would be better for an IDS.
\paragraph{rare attack classes} alongside macro, we should show per-attack recall for the rare ones. the whole point of working on the imbalance is to help out these classes. This makes it quite granular, so we aren't just comparing methods on their recall and precision tradeoff, but maybe one method is better at analysing sql injections and another at XSS.
